# 总结报告格式

## 输出方式

**不写任何文件**。报告直接打印到控制台（Markdown 文本，由终端渲染）。

## 字数硬上限：6000 字

不论 chat 还是 thread 模式，整篇报告 **≤ 6000 字**（中文字符 + 英文混合按 `len()` 估算）。超出时按 SKILL.md §5 压缩优先级处理，**不向用户确认**，直接产出压缩版。

## 报告骨架（中文，技术术语保留英文）

### chat 模式

```markdown
# 飞书群讨论总结 — <群名>

> 时间窗口：`<YYYY-MM-DD HH:MM:SS>` → `<YYYY-MM-DD HH:MM:SS>`（Asia/Shanghai）
> 生成时间：`<YYYY-MM-DD HH:MM:SS>`
> Chat ID：`<oc_xxx>`

## 概览

| 维度 | 数值 |
|------|------|
| 主线消息 | N 条 |
| 话题数 | M 个（含 K 条 thread 内回复）|
| 参与人 | P 人（活跃前 3：A / B / C）|
| 媒体 | 图片 X / 文件 Y / 视频 Z |
| 撤回 | R 条（已忽略） |

一句话总览（≤ 60 字）：本期群内主要围绕 XXX 展开，达成 N 项结论，遗留 M 个行动项。

## 主要讨论话题

> 按热度 / 重要性排序，每个话题独立一节。话题边界识别：优先按 thread_id 聚类；无 thread 的散落消息按时间 + 关键词聚类。

### 话题 1：<话题标题>

- **时间**：`<起>` ~ `<止>`
- **参与人**：A、B、C
- **背景 / 起因**：一段话说清触发点
- **关键发言**：
  - `[YYYY-MM-DD HH:MM] A`：核心观点摘录（≤ 30 字）
  - `[YYYY-MM-DD HH:MM] B`：……
- **进展 / 现状**：当前结论或待办

（重复 3 ~ 8 个）

## 关键观点 / 意见

> 仅列被多人附议、引发持续讨论、或来自核心 owner 的关键观点。

- **观点 1**（提出人：A，附议：B、C）：内容
- **观点 2**（提出人：D）：内容
- **争议点**（持有 X 的：A；持有 Y 的：B）：双方核心分歧

## 决策与结论

| # | 结论 | 决策人 / 拍板时间 | 关联话题 |
|---|------|-----------------|---------|
| 1 | <一句话结论> | A · `YYYY-MM-DD HH:MM` | 话题 1 |
| 2 | … | … | … |

> 没明确决策的争议**不要**塞进本节，写到「关键观点 / 争议点」即可。

## 行动项 & 后续步骤

- [ ] **@A** —— <事项描述> —— DDL: `YYYY-MM-DD` —— 关联话题 1
- [ ] **@B** —— <事项描述> —— DDL: 未明确 —— 关联话题 3
- [ ] **未指派** —— <事项描述> —— DDL: 未明确 —— 需补充负责人

> 行动项识别线索：消息中含「我来 / @X 来 / 跟进 / 推进 / 排期 / 周X 之前 / 截止」等关键词，或 owner 明确认领。

## 附录：媒体清单

| # | 类型 | key | 发送人 / 时间 | 描述 / 上下文 |
|---|------|-----|--------------|--------------|
| 1 | image | `img_v3_xxx` | A · `MM-DD HH:MM` | 报错截图 |
| 2 | file | `file_xxx`（`xxx.xlsx`） | B · `MM-DD HH:MM` | 数据明细 |
| 3 | media | `media_xxx`（视频, 12s） | C · `MM-DD HH:MM` | 复现步骤录屏 |

> 飞书内可通过 message_id 找到原始消息直接打开。本工具**不下载** image/file/media 本体。

## 附录：消息体量

- 主线已拉取页数：N 页（每页 50 条）
- thread 展开数：M 个
- 累计处理消息：T 条
- 累计 Token（估算）：~XXK
```

### thread 模式

```markdown
# 飞书话题讨论总结 — <入口一句话概括>

> 所属群：<群名>（`<oc_xxx>`，可选）
> Thread ID：`<omt_xxx 或 thread_id>`
> 入口消息时间：`<YYYY-MM-DD HH:MM:SS>`
> 拉取时间窗口：`<start>` → `<end>`（入口消息无论是否在窗内都保留）
> 生成时间：`<YYYY-MM-DD HH:MM:SS>`

## 概览

| 维度 | 数值 |
|------|------|
| 入口发送人 | A |
| 回复消息 | N 条 |
| 参与人 | P 人（活跃前 3：A / B / C）|
| 媒体 | 图片 X / 文件 Y / 视频 Z |
| 撤回 | R 条（已忽略） |

一句话总览（≤ 60 字）：本话题围绕 XXX 展开，达成 N 项结论，遗留 M 个行动项。

## 入口（讨论起因）

- **发送人 / 时间**：A · `YYYY-MM-DD HH:MM:SS`
- **原文摘录**（≤ 100 字）：`<入口消息文本>`
- **背景补充**（可选，仅当入口本身信息不足时由群名/上下文补充一两句）

## 关键观点 / 意见

- **观点 1**（提出人：A，附议：B、C）：内容
- **观点 2**（提出人：D）：内容
- **争议点**（持有 X 的：A；持有 Y 的：B）：双方核心分歧

## 决策与结论

| # | 结论 | 决策人 / 拍板时间 |
|---|------|-----------------|
| 1 | <一句话结论> | A · `YYYY-MM-DD HH:MM` |

## 行动项 & 后续步骤

- [ ] **@A** —— <事项描述> —— DDL: `YYYY-MM-DD`
- [ ] **@B** —— <事项描述> —— DDL: 未明确

## 附录：媒体清单

| # | 类型 | key | 发送人 / 时间 | 描述 |
|---|------|-----|--------------|------|
| 1 | image | `img_v3_xxx` | A · `MM-DD HH:MM` | 报错截图 |

## 附录：消息体量

- 话题内回复：N 条 · 入口：1 条
- 累计 Token（估算）：~XXK
- 仅访问 `container_id_type=thread`，未读取群主线
```

## 控制台输出

报告直接打印 Markdown 全文到控制台，末尾附一行元信息：

```
<报告 Markdown 全文，≤ 6000 字>

---
📊 <N 条主线 / M 个话题 / P 人 / X 媒体>（thread 模式则：<N 条回复 / P 人 / X 媒体>）· 窗口 <start>~<end>
```

> ⚠️ 不写文件，不询问"是否打开"。报告就在终端里，用户直接读。
> ⚠️ 仍要保证内容真实、不脑补；压缩是删次要项，不是编造。

## 准则

- **不编造**：消息里没有的结论 / 行动项 / DDL 一律标「未明确」，绝不脑补
- **直接引用**：关键发言用消息原文（必要时压缩到 ≤ 30 字），保留 `[时间 发言人]` 前缀，方便回溯
- **去噪**：纯打招呼 / 表情 / 单字「好」「收到」/ 撤回 都不进报告
- **隐私 / 边界**：邮箱、电话号、身份证号等敏感信息**不要**写进报告
- **中文为主**：技术术语、代码标识、API、Lark 字段名保留英文
- **md 转义**：所有可能被 md 当成格式化标记的标识符（`_xxx`、`*xxx`、`<xxx>`、`#xxx` 等）用反引号包裹
